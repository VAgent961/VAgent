## Files
- `index.html` — sign-in page (one screen, no scroll). Posts to /api/login.

Grid is the squarest one with no empty cells (4 rooms = 2x2). Right column: CEO office, messenger corner, café (120 spots), open desks. People are realistic `person()` figures: every colleague wears the same navy company suit with a gym build and very dark skin (ten variants `#p0..#p9` differ by hair/glasses, `VScene.people`), `#lead` same suit with light skin, `#ceo` all gold and bulkier, `#msgbot`; office.js gives every agent the same person each time (`personRef`, hash of its key; an agent that is a department's lead gets `#lead`, light skin). Every figure carries all poses, switched only by inherited CSS variables (office.css): `--as` standing arms, `--ad` typing at a desk, `--ar` reading a book, `--am` coffee mug, `--ls/--lsit` standing/seated legs, `--hs` headset, `--sitk:1` lowers the body onto a seat. At a desk (`.seat`) people sit with a headset and type; in the lounge office.js `startLife()` sets `data-pose` read (sofa/armchair seats, prop 'read' = `SEATS`, about half of resting people take one) or mug (walks to a free `room.coffee` point, drinks 8–18 s, walks back). Furniture is drawn with `box()` as true isometric pieces (sofa, armchair, lowTable, meeting, shelf, display, counter); a room keeps a `blocked` list so rest spots never land inside furniture. Returns {inner, vb, desks, deskRoom, rooms[{lead, desks, rest, box}], hot, cafe, cafeIdx, spotProp, ceo, helper}. Test with fake data: ~/agent-tools/site-checker/rooms-shot.js (ROOMS=n); close-ups with local files swapped into the live page: `LOCAL=<repo> node ~/agent-tools/site-checker/zoomshot.js`.

## Agent key + status
- Agent key = `<instanceId>:<workflowId>`.
- Name tags show on hover / focus / search only (they used to pile up over the desks); working = small typing bubble, failed = red ! badge. Resting agents spread over the lounge: each has its own usual spot (hash of key).
- A department's lead never sits: it stands at the room's lead spot (`leaddesk`) whether working or idle, while the team takes desks.
- Chats are kept in localStorage per target (`vagent-ceo`, `vagent-chat-<to>`, last 30 messages), so closing the drawer or the tab keeps the thread. A sent message also saves a `pending` bubble that is replaced in place when the reply lands, so reopening mid-answer still shows it working; a pending older than 3 minutes (tab was reloaded, request lost) renders as "that answer never came back".
- Talking to a department's lead (its drawer, or `lead:<id>`) stamps `vagent_departments.last_talk`; for the next 15 minutes every active `idle` employee in that department is reported as `working`, so the team sits at its desks and then drifts back to the lounge. Set in `api/talk.js`, applied in `_office.js`. `off` and `help` are left alone.
- Status: `working` → a desk in its department room (no department / room full → open desks); `idle` → its department lounge (no department / lounge full → café). Building is dark themed. · `idle` (active) → café · `off` (inactive) → café, asleep · `help` (last run failed <24h) → red mark.
- Calls to agent webhooks carry header `X-VAgent-Secret` (secret WEBHOOK_SECRET); protect webhooks in n8n with Header Auth "VAgent office secret".

An agent with no webhook (e.g. the Telegram-triggered Sniper Lead Machine) hands Start over to its department's chat agent (`flow` in openAgent: a runnable team-mate whose name has "chat", else the only runnable one) — it opens that drawer and sends `start` (`data-flow` + `pendingSay`).
